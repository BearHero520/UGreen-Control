## 一、版本更新概述

新版界面将功能划分为“概览”“灯光设置”“活动提示”“设备与高级”“BIOS 控制”“实验室”和“关于”，统一灯光、硬件监控与电源管理的操作入口。

v2.2.3 的主要更新包括：

- **优化灯控并发访问。** 针对 DX4600 页面刷新与后台智能灯效同时运行时出现的 LED controller busy 问题，减少重复总线探测、合并灯状态读取，并避免页面刷新请求重叠。
- **完善来电启动策略设置。** 当读取接口可用、当前策略显示为“未知”时，允许用户明确选择策略后重新保存，并校验实际结果。
- **改进 DXP4800S 灯控探测。** 完善 MCU 签名校验与总线重试流程。

**验证状态：上述相关更新已完成实机测试，测试结果正常。机型支持范围及各项硬件能力仍以应用内检测结果为准。**

## 二、安装与升级

系统要求：**fnOS 0.9.27 及以上，x86 平台**。安装与硬件控制需要相应的 root 权限。请避免与 LLLED 命令行版或其他灯控程序同时运行。

### 通过 FnDepot 添加应用源

本项目已收录至 [BearHero 应用源](https://github.com/BearHero520/FnDepot)，支持 FnDepot V2 外部应用源规范。

1. 使用支持 V2 外部源的 FnDepot 客户端，进入外部应用源设置。
2. 添加仓库地址：[https://github.com/BearHero520/FnDepot](https://github.com/BearHero520/FnDepot)。
3. 也可使用 [fnpack.json 直链](https://raw.githubusercontent.com/BearHero520/FnDepot/main/fnpack.json) 添加源。
4. 刷新源后，查找“UGREEN工具箱”，核对版本及架构，并按客户端提示安装。

**备注：应用源已更新，具体版本以 FnDepot 客户端刷新后的显示为准。** 本源为 BearHero 维护的个人应用源。

### 手动安装

1. 进入 v2.2.3 Release 页面，展开 Assets。
2. 下载 App.Native.UGreenLED-2.2.3.fpk 或 App.Native.UGreenLED.fpk，两者内容相同。
3. 打开 fnOS 应用中心，选择“手动安装”，导入 FPK 并完成安装。
4. 从 fnOS 桌面打开“UGREEN工具箱”，核对应用版本与机型识别结果。

旧版尚未提供“关于”页面时，可直接通过上述流程升级。

### 应用内检查更新

1. 进入“关于”，点击“检查更新”。
2. 检测到新版本后，通过“更新说明”查看变更内容，点击“下载升级包”获取 FPK。
3. 在 fnOS 应用中心手动安装升级包。
4. 安装完成后重新打开应用，在“关于”页面确认当前版本。

## 三、灯光模式与参数配置

需要根据硬盘和网络状态自动控制灯光时，选择“智能模式”。进入“灯光设置”，分别配置硬盘灯、网络灯和电源灯的颜色与亮度，完成后点击“保存灯光设置”。

![图3 硬盘状态颜色、亮度与配色方案（演示数据）](data/attachment/forum/202610/10/190947wqbrwzkm1leb6edd.jpg)

图3：硬盘活动、空闲、休眠及深度睡眠可分别设置颜色与亮度；离线或拔出状态自动关闭对应灯光。配色方案支持快速套用，修改后须保存生效。

“活动提示”提供磁盘读写和网络流量的速度闪动设置，可按需调整触发阈值。“关闭全部”用于关闭可用指示灯，“开启全部”用于保持可用指示灯常亮。

**DXP480T / Plus 功能范围：** 使用专用电源灯页面，仅支持红色和白色，不支持亮度调节。

## 四、硬盘灯映射配置

当指示灯与实际盘位对应关系不一致时，可先进入“设备与高级 → 硬盘与 LED 映射”，执行“重新检测”。如需手动校正，进入“实验室”进行绑定。

![图4 硬盘灯绑定方式与操作流程（演示数据）](data/attachment/forum/202610/10/190947de46wwhk6o66eye6.jpg)

1. 选择绑定方式。“按位置绑定”保持机箱盘位对应关系，更换硬盘后仍按位置生效；“按硬盘绑定”根据硬盘序列号保存对应关系。
2. 点击“开始检测并点亮全部硬盘灯”，确认实际灯位。
3. 为各目标选择 LED 通道，使用“闪烁此灯”逐项验证。
4. 确认对应关系后，点击“保存自定义映射”。需要恢复默认规则时，使用“恢复自动映射”。

检测模式会临时接管硬盘灯，请在无硬盘维护操作时执行。设备名 /dev/sda、/dev/sdb 的顺序不应作为物理盘位的唯一判断依据。

## 五、风扇模式与自动温控

应用根据硬件检测结果显示 BIOS 控制入口及可用功能。配置前应确认精确机型、控制器状态和页面提示；实验性写入按界面要求进行风险确认。

![图5 BIOS 控制器与机型保护信息（演示数据）](data/attachment/forum/202610/10/190947gflzvz2v9mn226ve.jpg)

![图6 温度转速趋势与风扇模式（演示数据）](data/attachment/forum/202610/10/191005rssov6ffmyjtcjt5.jpg)

- **原厂兼容自动：** 使用当前机型已恢复的原厂温度—PWM 曲线进行调速。
- **自定义自动：** 根据 CPU、HDD、NVMe 温度阈值和自定义 PWM 曲线进行调速。
- **固定转速：** 按指定 PWM 持续运行，不随温度变化自动调整；应用时会停止自动温控。

![图7 原厂兼容自动模式的温度—PWM 曲线（演示数据）](data/attachment/forum/202610/10/191005ib7b207142vddzaz.jpg)

图7：选择模式后，需使用对应的启动或应用按钮执行配置，并确认回读状态。自动温控由软件守护程序执行，不修改 BIOS 固件；其运行依赖相应服务。

参数调整后应观察温度与转速趋势。曲线需结合机型、硬盘数量、实际负载及环境温度设置，截图参数仅用于界面说明。

## 六、电源管理功能

![图8 来电启动与网络唤醒设置（演示数据）](data/attachment/forum/202610/10/191052a1u8bs213u6ixiiw.jpg)

### 来电启动策略

支持“自动开机”“保持关机”及“恢复断电前状态”。选择后点击“保存来电启动策略”，以实际回读结果确认生效状态。读取接口可用但当前策略为“未知”时，新版支持明确选择策略后重新保存。

**DX4600 升级说明：** 升级后建议重新选择并保存一次来电策略。应用在硬件写入成功后保存选择，并在服务启动等时机恢复配置。该机制属于软件恢复，不修改 BIOS NVRAM，因此应保持应用随系统启动。不同精确机型的验证结论分别适用。

### 网络唤醒 WOL

在支持的设备上选择“允许魔术包唤醒”并保存，通过局域网内另一台设备发送 Magic Packet 验证唤醒结果。此功能配置 NAS 的网络唤醒能力，公网远程唤醒还取决于网络环境与相应配置。

### 定时开关机

设置执行星期、开机时间和关机时间，保存后核对执行信息。首次使用建议在可现场确认的时段验证，并避开备份、下载和文件传输任务。定时关机前会先设置下一次 RTC 唤醒；写入或回读失败时，应用将取消关机。

来电启动用于供电恢复后的启动策略，WOL 用于网络魔术包唤醒，RTC 用于按计划启动。各项能力及可选策略以当前设备检测结果为准。

## 七、诊断与技术反馈

出现灯控异常或策略未生效时，首先核对机型识别结果及其他灯控程序的运行状态，再进入“设备与高级 → 应用诊断日志”检查 WARN / ERROR 信息。需要详细排查时，可临时切换至 DEBUG，完成后恢复 INFO。

“一键下载诊断包”可导出排查信息。提交反馈时，请提供精确机型、fnOS / BIOS / 应用版本、复现步骤、预期结果、实际现象及发生时间。公开分享前应检查诊断内容是否包含不宜公开的信息。

**兼容性说明：** 单项功能实测通过不代表同系列所有机型、所有 BIOS 功能均已验证。实验性或待验证功能应遵循应用内的支持状态和操作提示。
