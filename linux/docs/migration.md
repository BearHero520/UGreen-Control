# 群晖 / TrueNAS 适配记录

当前分支：`synology-truenas`。本轮只修改平台应用层、部署文件和测试。
根目录 fnOS 的既有未提交修改保留；没有提交、推送、发布或进行真实硬件写入。

## 已落地

- 新增独立 HTTP Web 服务；拒绝 root Web 身份；所有敏感读取和控制请求需要独立管理员鉴权。
- Web 和 root 硬件服务通过本地 Unix socket 分离，固定方法 / 路由、UID 凭据与请求体限制。
- 删除旧的无鉴权 HTTP 旁路；CGI 改为仅供本地 broker 调用的适配器。
- 通用设置不能修改 BIOS 风险确认、曲线启用、定时电源计划或伪造硬件机型。
- 移除运行入口的 fnOS 路径和 manifest 依赖；LED 只使用 bundled CLI。
- 新增 x86_64 Dockerfile、群晖 / TrueNAS Compose 生成器、目录权限约束、共享宿主锁和 root 开机准备命令。
- 默认关闭 LED / BIOS 写入，不自动启动 LED 或恢复 BIOS 策略；自动曲线因退出接管尚未验证而暂不开放启停。
- 宿主资源和磁盘活动仅从元数据采样，无原始存储盘透传；宿主网络按 carrier 与字节统计。
- 版本、说明与更新入口独立于 fnOS，不再提供 FPK 升级链接。
- 两平台部署说明、权限矩阵和独立的 CI 镜像构建检查。

## 本地验证（Windows，2026-10-28）

- Python 导入校验、策略和真实 HTTP 测试通过；Linux Unix socket roundtrip 测试在 Windows 跳过。
- 普通配置绕过 BIOS、未登录访问、错误身份、跨站写入、超大请求、源码路径和越界设备映射均有负向测试。
- Shell 元数据 fixture 通过；没有访问真实控制设备或存储盘。
- 前端类型检查、7 项测试和构建通过。
- 固定载荷 SHA256 验证通过，Linux LED CLI 与标准 fnOS 包内 CLI 字节一致；未修改上游程序或插件。

后续已使用 QEMU 隔离 Linux、Docker 28.3.3 / Compose 2.36.2 完成镜像构建与启动、
真实 Unix socket 凭据、POSIX ACL、共享锁、进程崩溃、容器重建和 AppArmor 冷启动恢复验证。
群晖已新增原生 SPK 开发包，并通过原生服务模拟安装、不可篡改程序、就绪通知和升级保留检查。
CI 配置已添加但没有触发远程运行，不能把预期的 CI 结果当作已通过。
